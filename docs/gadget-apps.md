# Приложения как файлы проекта Mnemos

ADR 0028 Mnemos, этапы 1–3. Этот файл — справка для навыков opencode и для тех, кто пишет гаджеты.

## Формат файла

Тип содержимого узла — `application/vnd.cloudflareos.app+json`, формат в каталоге версий — `cloudflareos.app`.
Тело узла — JSON:

```json
{
  "format": "cloudflareos.app",
  "formatVersion": 1,
  "document": {
    "manifest": {
      "title": "Список дел отдела",
      "description": "Общий список задач",
      "collaborative": true,
      "session": true,
      "formatVersion": 1,
      "permissions": ["directory"]
    },
    "modules": { "client.js": "…", "server.js": "…" }
  }
}
```

Проверка строгая (`workshop-shared/src/gadget-app.ts`): лишние поля и модули — отказ.

- `title` — одна строка, до 120 знаков.
- `description` — до 2000 знаков.
- `collaborative` — `true`: один экземпляр и одна база на файл для всех, у кого есть доступ; `false`: у каждого свой экземпляр.
- `session` — класс `Gadget` объявляет `session(caller)`. Для `collaborative: true` обязателен: общий экземпляр
  отдаёт странице только то, что вернул `session(caller)`, и никогда сам объект `Gadget`. Оболочка ставит признак
  при сохранении, если в `server.js` есть `session(`.
- `permissions` — пока только `directory` (справочник людей и отделов).
- `client.js` — до 2 МиБ, `server.js` — до 1 МиБ, весь файл — до 4 МиБ.

Других модулей нет: сборка кладёт всё в `client.js` и `server.js`. Подключений (bindings) у приложения нет, сети у сервера нет.

## Сервер гаджета: кто вызывает

`server.js` экспортирует класс `Gadget` (Durable Object). Если в нём есть метод `session(caller)`, оболочка
вызывает его один раз на каждое подключение страницы, а страница работает с тем, что он вернул.

```js
import { DurableObject, RpcTarget } from "cloudflare:workers";

class Session extends RpcTarget {
  constructor(app, caller) { super(); this.app = app; this.caller = caller; }
  me() { return { name: this.caller.name, canEdit: this.caller.access === "edit" }; }
  addTask(text) {
    if (this.caller.access !== "edit") throw new Error("Только просмотр");
    return this.app.addTask(this.caller.principal, text);
  }
}

export class Gadget extends DurableObject {
  session(caller) { return new Session(this, caller); }
  addTask(principal, text) { /* this.ctx.storage */ }
}
```

Правила для `session(caller)`:

- не возвращать `this` (сам объект `Gadget`) и ничего, через что страница могла бы вызвать сервер от имени
  произвольного человека;
- каждый метод объекта, который вернул `session()`, берёт человека из сохранённого `caller`
  (`caller.principal`, `caller.access`), а не из аргументов вызова;
- методы класса `Gadget`, принимающие principal аргументом, со страницы недоступны: их зовёт только объект сессии.

`caller` — только данные, без ссылок RPC, хранить можно сколько угодно:

| Поле | Что это |
|---|---|
| `principal` | Устойчивый ключ человека в Mnemos. По нему разделяются данные по людям. |
| `name` | Имя для показа. |
| `access` | `"read"` или `"edit"` — право на файл приложения. |
| `directory` | Есть, только если в манифесте разрешение `directory`: `{ people: [{id, name}], departments: [{id, name, members: [{id, name}]}] }`. Снимок на момент подключения. В общем экземпляре — только то, что видят одновременно открывший и тот, кто с правом правки запустил работающую версию; в своём экземпляре — справочник открывшего. |

Право проверяется оболочкой при открытии, на каждом вызове (полная проверка не реже раза в 30 с) и по
таймеру, пока страница открыта; срок каждой проверки — 10 с. Потеря доступа, понижение права, просрочка
проверки или другой человек, установка или узел в ответе Mnemos закрывают связь; новое подключение
придёт с новым `caller`. Без `session()` работает только приложение без совместной работы (в своём экземпляре).

В предпросмотре правок гаджета беседы (рабочее место, до сохранения в проект) `session()` тоже вызывается:
`principal` — `workspace:<id пользователя оболочки>`, `access` — `"edit"`, справочника нет. Данные предпросмотра
отдельные. У гаджета, привязанного к узлу, предпросмотра нет: кода в рабочем месте у него нет.

## Где живёт экземпляр

Durable Object `MnemosAppDurableObject`, два вида ключей из ответа Mnemos о праве (проект и узел — как их назвал
Mnemos, не как их прислала страница), и адрес установки Mnemos — разные установки с совпавшими id не делят
экземпляр:

- общий: `[установка, организация, проект, узел]` — совместные приложения;
- свой: `[установка, организация, проект, узел, principal]` — приложения без совместной работы.

Сервер гаджета исполняется в объекте facet'ом через `LOADER` с `globalOutbound: null` и пустым `env`. Объект
хранит работающую версию (текст узла кусками), журнал открытий и смен кода (последние 500 записей). Новая версия
перезапускает facet; база приложения сохраняется.

В общем экземпляре работает только опубликованная версия узла (прошедшая публикацию и согласование, как у
документа). Личные версии (черновики автора и участников) в общем экземпляре не запускаются; своё приложение
(без совместной работы) запускает и личную версию в своём экземпляре. Сменить работающую версию может только человек с правом правки («Опубликовать», «Запустить эту
версию»). Без права правки — лишь первый запуск пустого экземпляра последней опубликованной версией; проверка
«экземпляр пуст» и запись делаются в объекте одним шагом. Код версии оболочка читает из Mnemos сама, правами
открывшего; открывший должен иметь доступ к самой работающей версии.

## Копии приложения без совместной работы (этап 3)

«Поделиться» приложением с `collaborative: false` раздаёт не доступ к данным, а копии.

- Автор выбирает людей (или открывает проект отделу или организации). Приглашение — только на чтение.
- Получатель, открыв приложение («Поделились с вами», проект, ссылка), не запускает оригинал. Он выбирает
  свой проект, и оболочка создаёт там узел-копию: личная версия его проекта, текст — последняя
  опубликованная версия автора, своя пустая база. Повторное открытие оригинала открывает ту же копию.
- Копия — узел получателя: код правит только он, «Опубликовать» публикует его проект, не оригинал.
- Версия для копий: оболочка хранит последнюю опубликованную версию оригинала (объект
  `["mnemos-app-release", установка, организация, проект, узел]`). Её записывает публикация автора из шапки
  и любое открытие человеком, который видит историю узла в Mnemos; текст читается из Mnemos его правами,
  сумма сверяется, более старая публикация не заменяет более новую. Приглашённый поимённо получает то, что
  записал автор, — черновики автора (личные версии) в копии не попадают.
- Обновление: когда автор публикует новую версию, в шапке копии — «Доступно обновление от автора» с
  «Обновить» и «Не сейчас». «Обновить» записывает версию автора новой версией копии (оболочка сама
  выгружает текст в хранилище по билету Mnemos и сверяет сумму после записи), экземпляр перезапускается,
  база сохраняется. Сама копия не обновляется никогда.
- Отзыв доступа к оригиналу: копия остаётся и работает, обновления больше не предлагаются; шапка и
  «Версии» копии это объясняют.
- Получатель без права правки не может запустить оригинал в своём экземпляре ничем, кроме последней
  опубликованной версии (сервер отказывает личным и старым версиям).

Для `collaborative: true` «Поделиться» работает как раньше: доступ к общему экземпляру.

## Кто получает код

Решение владельца 29.09 (ADR 0028 Mnemos, п. 4): тело узла приложения платформа не выдаёт никому, даже человеку
с правом правки. Браузер получает только `client.js` работающей версии во фрейм — без этого экран не запустить.
`server.js` и тело узла целиком закрыты.

- Тело узла читает только сервер оболочки для запуска и манифеста, служебным путём Mnemos
  `GET /v1/projects/{p}/nodes/{n}/app-code[?version=<event_id>|private:<head>]` с заголовком
  `X-Mnemos-Shell-Key` и токеном человека (контракт — `docs/seams.md` Mnemos). Ключ живёт только в
  gatekeeper-mnemos (`MNEMOS_SHELL_KEY`, передаётся через `PASSTHROUGH_GATEKEEPER_VARS` в `run-dev-server.js`).
  Метод `nativeDownloads.selector.appCode` есть только у служебного кадра (`AppUiContext.appCode`, его ставит
  `UserDurableObject.miniAppMnemos`); его зовут `nodePorts.text`/`version` в `workshop-backend/src/server.ts`,
  через них идут запуск, манифест, копии и обновления копий. Сервер получает билет на 10 с и сам сверяет длину
  и SHA-256. Без ключа — «Запуск гаджетов не настроен: нет ключа оболочки.», отказы Mnemos (`shell_key_rejected`,
  403 права, `not_a_gadget`) — своими текстами.
- Кадр для браузера (`getGatekeeperApp` → `openUiApp`) признака `appCode` не несёт: его `appCode` и все выдачи
  шлюза (`nativeDownloads.select`, `textDownloads` — в том числе «Скачать файл» в «Материалах» и «Истории
  приёма», импорт публикации в гаджет, чтение документа агентом беседы через `MNEMOS`) отказывают в теле узла
  текстом `APP_CODE_CLOSED` (`workshop-shared/src/gadget-app.ts`). Mnemos и сам отвечает на них 403
  `gadget_code_closed` — шлюз переводит его в тот же текст.
- В рабочее место код узла не кладётся ни при каком праве: у гаджета, привязанного к узлу, нет вкладки «Код»,
  список гаджетов не отдаёт странице его `filesRoot`, `exportAppModules` отказывает, `restoreAppModules` убран.
- Агент беседы код не читает и не правит: `readFile`, `writeFile`, `editFile` и обращение к гаджету из
  `executeCode` отказывают с подсказкой передать задачу агенту кода (`gadgetWork`).
- Править приложение можно только через агента кода (opencode, мост `gatekeeper-mnemos/src/gadget-bridge.ts`):
  новая сборка ложится личной версией узла. В ленте беседы у задачи гаджета видны только имя файла или короткая
  команда и итог шага, без вывода инструментов. Агенту кода велено не приводить код в ответе
  (`/opt/gadget-kit/AGENTS.md`).
- «Вернуть» в «Версиях» делает Mnemos сам (`restorePublication` селектора записи, как у документа): выбранная
  версия становится новой личной версией узла, текст через браузер не идёт. Своё приложение сразу запускает её
  в своём экземпляре; совместное — после публикации.
- «Сохранить в проект» остаётся только у гаджета беседы (код в его рабочем месте написан в беседе): после
  сохранения гаджет привязан к узлу, и его код закрывается так же.
- Предпросмотр личной версии совместного приложения (ADR 0028 п. 2): у того, кто правит файл, личная версия
  (или выбранная в «Версиях» неопубликованная) открывается в отдельном экземпляре — ключ
  `["mnemos-app-preview", установка, организация, проект, узел, principal]`, вид объекта `preview`, своя пустая
  база. Код читается служебным путём app-code (`version=private:<head>`) правами человека; общий экземпляр не
  трогается. Шапка: «Предпросмотр личной версии — данные не сохраняются для других», «Опубликовать» и, если
  есть опубликованная, «Показать опубликованную». Читатель предпросмотр не получает
  (`AuthenticatedApi.openMnemosAppPreview` отказывает).
- Поэтому «Поделиться копией» безопасно: получатель получает то же приложение, но не его код.
- Код рабочего места: при привязке гаджета к узлу (`setMnemosApp`) и при первой подписке на код старого рабочего
  места (`subscribeToCode`) файлы такого гаджета удаляются из Y.Doc (`OverseerImpl.purgeClosedCode`), и сразу
  пишется снимок без их текста: подписка с любой версии до чистки получает снимок, а не историю. Правки,
  задевающие корень такого гаджета, `updateCode` отвергает; шаблон (`createBlueprint`) из него не делается.
- Ответ агента кода в задаче гаджета фильтруется на сервере (`workshop-backend/src/gadget-answer.ts`, зовёт
  `chat-code-work.ts`): блоки в тройных кавычках длиннее 5 строк и строки от 40 знаков, совпадающие с `server.js`
  или `client.js` сохранённой сборки, заменяются на «(код гаджета не показывается)». По кусочкам ответ не
  течёт — в ленту уходит один раз, уже отфильтрованный. У задач кода проекта ответ прежний.
- Сумма версии: `codeWorkSaveGadget` передаёт службе исходников `body_sha256` — hex SHA-256 всех байтов тела
  узла, записанного мостом. Это та же величина, что `sha256_hex` у app-code, сумма версии у экземпляра
  (`gadgetAppSha256`) и `sha256` в связи копии с оригиналом.

## «Сделать своей»

Решение владельца 29.09. Владелец копии (`collaborative: false`) нажимает «Сделать своей» в шапке копии или в
«Версиях» и подтверждает: «Вы сможете менять гаджет через агента кода. Обновления от автора больше не будут
приходить». Связь копии (`MnemosAppConnection.makeOwn`) проверяет право чтения оригинала правами получателя,
gatekeeper-mnemos (`codeWorkForkGadget`) проверяет его ещё раз и зовёт `POST /v1/workspace/gadget-sources/fork`
с ключом агента получателя и суммой версии, из которой сделана копия. После ответа 204 связь с оригиналом
снимается: обновления не предлагаются, правка — через агента кода с `resource` копии (исходники восстановятся).
Отказы: `no_sources` — «исходники этой версии не сохранились», 503 — хранилище недоступно, 400 — копия указана
неверно; связь с оригиналом при отказе остаётся.

## Тема и токены во фрейме гаджета

Касается любого фрейма гаджета: гаджет беседы, приложение из проекта, встроенные редакторы документа,
таблицы и презентации, экран в Telegram Mini App. Код — `workshop-frontend/src/gadgetHostTheme.ts`,
разметка фрейма — `gadgetSandbox.ts` (`createSandboxedHtml`).

### Что оболочка кладёт во фрейм при создании

Первый кадр гаджета уже в теме и цвете человека, без мигания:

```html
<html data-mode="dark" style="--host-accent:#ae4b14;--host-accent-hover:…;…;--host-neutral-tint:1">
<head>
  <meta http-equiv="Content-Security-Policy" content="…">
  <style id="mnemos-host-tokens">:root:root:root{--color-kumo-base:light-dark(…);…}</style>
</head>
<body><script type="module" src="data:…код оболочки + код гаджета…"></script></body>
```

- `data-mode` — `light` или `dark`. На сайте берётся с корня страницы оболочки (учитывает «как в системе»),
  в Mini App — из темы Telegram (`colorScheme`).
- Переменные акцента на корне (только эти имена):

| Переменная | Значение | Что это |
|---|---|---|
| `--host-accent` | HEX | заливка основной кнопки, акцент |
| `--host-accent-hover` | HEX | наведение на основную кнопку |
| `--host-accent-text` | HEX | текст акцента и ссылки в светлой теме |
| `--host-accent-tint` | HEX | подложка выделения в светлой теме |
| `--host-accent-text-dark` | HEX | текст акцента и ссылки в тёмной теме |
| `--host-accent-tint-dark` | HEX | подложка выделения в тёмной теме |
| `--host-accent-hue` | число 0–360 | оттенок акцента: им едва окрашены нейтральные поверхности, линии и текст |
| `--host-neutral-tint` | число 0–1 | сила этого оттенка; 0 у серого цвета организации |

  Оттенки считает `accentShades` (`workshop-shared/accent-theme.ts`), как для самой оболочки. Цвет человека
  не HEX — действует зелёный Mnemos.
- Базовые токены Mnemos (`HOST_BASE_CSS`) — в `<head>` до кода гаджета: поверхности, линии, текст, акцент,
  статусы (`--color-kumo-*`, `--text-color-kumo-*`, `--color-selection-*`) со значениями оболочки через
  `light-dark(светлое, тёмное)`, шрифт (`--font-sans`, `--font-mono`, без файлов шрифтов), шкала текста
  DESIGN.md (`--text-page-title` … `--text-counter` с интерлиньяжем, трекингом и начертанием), скругления
  (`--radius-sm` … `--radius-2xl`), `--container-page`.
  - Селектор `:root:root:root` сильнее правил темы Kumo, которые сборка гаджета выводит вне слоёв. Поэтому
    гаджет на Kumo получает цвета Mnemos, а не Cloudflare, без своих литералов.
  - `color-scheme` оболочка не ставит. Тёмные значения `light-dark()` включает сам гаджет правилом
    `[data-mode="dark"] { color-scheme: dark }`; Kumo (`@cloudflare/kumo/styles`) делает это сам. Светлые
    редакторы документа, таблицы и презентации поэтому остаются светлыми в тёмной теме оболочки.

### Сообщение при смене

Смена темы (в том числе системной) или акцента приходит без перезагрузки фрейма одним видом сообщения:

```js
{ type: "host-theme", mode: "light" | "dark", vars: { "--host-accent": "#176b9a", … } }
```

То же сообщение оболочка шлёт после каждого рукопожатия RPC (фрейм мог перезагрузиться со старой разметкой).
В Mini App разметку фрейма оболочка собирает в момент, когда фрейм сообщил «готов», — с темой на этот момент.

### Как гаджет применяет

Ничего делать не нужно. Код оболочки в начале модуля фрейма, до кода гаджета, слушает `message`:

- принимает только сообщение от родителя (`event.source === window.parent`) с `type: "host-theme"`;
- `mode` ставит в `data-mode` корня, только если это `light` или `dark`;
- из `vars` берёт только имена из таблицы выше; HEX — `^#[0-9a-fA-F]{6}$`, оттенок — число до 360,
  сила — от 0 до 1. Остальное отбрасывается: сообщение не может подставить в страницу произвольный CSS.

Слушатель гаджета, если он есть, получает то же сообщение уже после применения — например, чтобы
перерисовать холст. Прежнее сообщение `host-accent` больше не отправляется и не принимается.

### Строгий CSP

Политика фрейма не менялась: `default-src 'none'; style-src data: 'unsafe-inline'; connect-src 'none'` и так
далее. Токены — встроенный `<style>`, `'unsafe-inline'` его разрешает; ни `@import`, ни `url()`, ни
`@font-face` в нём нет. Проверено стендом: собранный шаблон gadget-kit во фрейме оболочки — 0 нарушений CSP.
